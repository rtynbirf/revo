# FORMAT: layout.json v1 — полная спецификация

> Канонический формат данных REVO. Этот документ — 1:1 зеркало `validate()` в `revo.py`:
> если код и документ разошлись — это косяк, чинится одним коммитом (AGENTS.md).
> Контекст метода: [SPEC.md](../SPEC.md) §2 · архитектура: [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. Корень документа

```json
{
  "canvas":  { "w": 1280, "h": 720 },
  "style":   { "mood": "...", "palette": { "base": "#0b0f1a", "primary": "#…", "accent": "#…", "warm": "#…" },
               "light": "...", "perspective": [0.5, 0.47] },
  "elements": [ { "id": "led-wall", "bbox": [430, 180, 850, 430], "z": "far",
                  "role": "teal LED status wall glowing in the deep background",
                  "color": "#14b8a6", "glow": true } ]
}
```

## 2. Поля корня

| Поле | Тип | Обяз. | Правила (из `validate()`) |
|---|---|---|---|
| `canvas` | object | да | — |
| `canvas.w`, `canvas.h` | int | да | целые, **64..4096** каждый; иначе ошибка `canvas.w/h — целые 64..4096` |
| `style` | object | нет | всё необязательное: отсутствие заполняется значениями по умолчанию на рендере |
| `elements` | list | да | **непустой** список; иначе `elements — непустой список` |

## 3. Поля элемента (зоны)

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | string | да (ошибка `нет id`) | уникальный человекочитаемый якорь: `racks-left`, `human` |
| `bbox` | [int,int,int,int] | да | `[x0,y0,x1,y1]` в пикселях полотна; все значения int; иначе `bbox = [x0,y0,x1,y1] целыми`; нарушение границ → `bbox вне полотна WxH`; требуется `x0<x1`, `y0<y1` |
| `z` | string | нет (по умолч. `mid`) | глубина: `far` \| `mid` \| `near`; иное → `z ∈ {far, mid, near}` |
| `role` | string | нет | описание содержимого зоны **на английском** — идёт в компилятор промпта как есть |
| `color` | string | нет | hex (`#14b8a6`); без него — `palette.accent` |
| `glow` | bool | нет | свечение зоны (glow-слой в offline-рендере, бонус критика) |

Валидатор пропускает дополнительные поля (вперёд-совместимость с v2: image refs, typography).

## 4. Глубина z — константы ядра (не придумывать свои)

| z | Порядок отрисовки | Z_FADE (растворение в фоне) | Z_WEIGHT (вес в score критика) |
|---|---|---|---|
| `far` | 1-й | 0.62 | 0.8 |
| `mid` | 2-й | 0.30 | 1.0 |
| `near` | 3-й | 0.00 | 1.2 |

Отрисовка и сортировка всегда far→near; компилятор промпта перечисляет зоны near→far
(ближние — первыми словами). Порог приёмки критика: `PASS_SCORE = 7.5`.

## 5. Семантика style

- `mood` — общий характер сцены (в компиляторе идёт первым предложением).
- `palette`: `base` — цвет полотна/фона (по умолчанию `#0b0f1a`); остальные ключи — свободные
  (`primary`, `accent`, `warm`…), попадают в промпт строкой `palette: primary #…, accent #…`.
- `light` — описание света, попадает в промпт как `lighting: …`.
- `perspective` — `[x, y]` в долях 0..1, точка схода: крест на скелете, строка
  `one-point perspective, vanishing point at (X, Y)` в промпте.

## 6. Позиционные слова (правило компилятора — детерминизм)

Центр bbox → нормированные координаты → слова:
- X: `< 0.34` → `on the left`; `> 0.66` → `on the right`; иначе `in the center`
- Y: `< 0.30` → `upper part`; `> 0.72` → `lower part`; иначе `middle ground`

Формула зоны в промпте: `"{role} {позиция}"`. Поэтому одинаковый layout даёт
байт-в-байт одинаковый промпт — фундамент воспроизводимости (N-02).

## 7. Эталонные примеры

- [`layouts/datacenter.json`](../layouts/datacenter.json) — 1280×720, перспектива [0.5, 0.47],
  7 зон: led-wall (far) → racks-left/right (mid) → ceiling (far) → floor/aisle/human (near).
- [`layouts/karaoke-stage.json`](../layouts/karaoke-stage.json) — 6 зон, неон-сцена.
- Любой кадр клетки: `demo/auto/*/__run.json` → layout.json рядом.

## 8. Ошибки валидации (точные тексты — на них завязаны тесты/UI)

- `canvas.w/h — целые 64..4096`
- `elements — непустой список`
- `elements[i](id): bbox = [x0,y0,x1,y1] целыми`
- `elements[i](id): bbox вне полотна WxH`
- `elements[i](id): z ∈ {far, mid, near}`
- `elements[i](id): нет id`

Exit-коды CLI: валидно → 0 (`VALID ✓`), невалидно → 2 (`INVALID:` + список), сервер M2 → HTTP 400.

## 9. Дорожная карта формата (не ломать v1)

- **v1.1 (M5):** опциональные `image_ref` (ссылка на картинку-референс зоны — прямо по посту Reve)
  и `typography` (текст, шрифт-класс, выравнивание) — валидатор уже пропускает доп. поля.
- **v1.2 (M5):** `image2layout` порождает лейауты с 5..50 зонами; валидатор получит верхний лимит
  64 и предупреждение при >20 (F-26/F-27).
- **Запрещено навсегда:** переименование существующих полей v1, переход bbox на доли 0..1
  (урок полимат-гена: там доли, здесь пиксели — при импорте конвертировать, не смешивать).
