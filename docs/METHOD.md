# Метод в одну страницу: почему layout → render

## Проблема
Свободный текстовый промпт — лотерея: модель сама решает, где что стоит. Двигать объект —
значит перебрасывать слова и молиться.

## Ставка Reve
Сцена = **структура + рендер**. Структура (layout) фиксирует зоны, глубину, свет, палитру.
Рендер — обязательство исполнить структуру. Композиция перестаёт быть случайной:
- **управляемость** — двигаешь bbox, а не слова;
- **воспроизводимость** — тот же layout → тот же план кадра;
- **проверяемость** — сравнил рендер со скелетом, отклонение видно глазом.

## Как это сделано здесь (4 шага, один файл `revo.py`)
1. **validate** — схема: полотно 64..4096, bbox внутри, z ∈ {far, mid, near}. Битая структура не доходит до рендера.
2. **skeleton** — PNG-скелет: рамки зон с подписями и глубинными цветами, крест точки схода.
3. **prompt** — компилятор: элементы сортируются от near к far, позиция слова вычисляется из центра bbox (left/center/right × upper/middle/lower), добавляются палитра, свет, перспектива. Никакой ручной отсебятины.
4. **render + merge** — offline-вектор (тот же layout, детерминировано) и/или генерация; склейка «было → стало».

## Отличие от демо в polymath-gen
`examples/reve_method_demo` — картинки-доказательство, снятые руками.
REVO — **код**: любой layout JSON проходит тот же путь автоматически. Демо можно повторить
одной командой, а скелет/offline-рендер не требуют ни сети, ни ключей.
