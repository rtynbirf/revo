## 2. Первоисточник метода: «The Layout Bet» (выжимка дословного смысла)

Полный текст — в архиве (`context/reve-blog-layout-bet.txt`, оригинал: blog.reve.com/posts/the-layout-bet/).
Суть, без искажений:

1. Текст — неоднозначное промежуточное представление; «неоднозначность — враг контроля».
   Правишь слова — меняется вся картинка.
2. Ставка Reve: заменить прозу на **layout** — структурное иерархическое описание изображения,
   где у каждого элемента есть **место, размер, локальное описание** и опциональные атрибуты
   (**ссылки на изображения, цвет**).
3. Layout — «позвоночник» картинки, как **HTML для веб-страницы** или **SVG для вектора**:
   отделяет семантику от пиксельного рендера.
4. Layout — **общий интерфейс человека и ИИ-агентов**: точный невербальный визуальный контроль.
   Уточнение результата — либо **естественным языком поверх лейаута**, либо **прямым редактированием структуры**.
5. Reve построила **Large Layout Model**: на вход любая комбинация лейаутов, инструкций и картинок;
   модель выводит лейаут из внутреннего «следа размышления», затем рендерит пиксели.
6. Данные: миллиарды изображений, dense human annotations; continued pretraining + post-training
   **открытых LLM (Qwen)** под пространственные рассуждения вокруг лейаута.
7. Результаты их абляций: layout-модели стабильно бьют prompt-модели равного размера;
   **реконструкция**: CLIP-сходство растёт с числом регионов — 0.865 (0 регионов) → 0.905 (10) →
   0.913 (20) → 0.923 (30) → 0.927 (40) → 0.929 (50); скейлинг-законы действуют и по размеру
   модели, и по числу регионов («visual thinking context»).
8. Декларация о будущем: генерация изображений как **program synthesis** — общий кодо-подобный
   семантический посредник, который читают и пишут люди и агенты.

**BibTeX (из поста):** `@misc{reve2026layoutbet, title={The Layout Bet}, author={{Reve Team}}, year={2026}, month={June}}`

## 4. Целевая система REVO-APP (архитектура верхнего уровня)

```
текст задания ──► МОЗГ (compose: LLM-ярус | 8 архетипов офлайн)
                      │ layout.json  ←──► РЕДАКТОР (UI-канвас зон / CLI / API)
                      ▼
              [validate] ── битое не проходит
                      ▼
              [skeleton PNG]  — человекочитаемая структура
                      ▼
              [prompt] — детерминированная компиляция ИЗ структуры
                      ▼
              РЕНДЕР-БЭКЕНДЫ: offline-вектор │ zai │ (M5: comfy/sd-адаптеры)
                      ▼
              [критик-глаза: зоны, score 0..10, вердикты] ── слабо? ──► рефайн ──► снова
                      ▼
              merge «было → стало» · проекты/галерея (M4) · AUTO-PILOT (CI, живой)
```

Подробности слоёв: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · формат: [docs/FORMAT.md](docs/FORMAT.md) ·
API: [docs/API.md](docs/API.md) · карта экранов оригинала: [docs/RESTORE-APP.md](docs/RESTORE-APP.md).

## 5. Функциональные требования

Формат строки: **F-xx [P0|P1|P2] [ГОТОВО|ПЛАН M?]** — формулировка. *Приёмка:* команда/способ.
P0 = без этого «100%» не засчитывается. P1 = нужно для продуктовости. P2 = желательно.

### Блок A. Ядро метода (M0)
- **F-01 [P0] [ГОТОВО]** Формат `layout.json` + строгий `validate`: полотно 64..4096 int; `elements` непустой список; bbox `[x0,y0,x1,y1]` int внутри полотна; `z ∈ {far,mid,near}`; наличие `id`. *Приёмка:* `python3 revo.py validate layouts/datacenter.json` → `VALID ✓`, exit 0; битый файл → exit 2.
- **F-02 [P0] [ГОТОВО]** `skeleton`: PNG-скелет структуры (рамки зон с id/role, цвета глубины, крест точки схода). *Приёмка:* `python3 revo.py skeleton layouts/karaoke-stage.json -o /tmp/s.png` → файл существует, размер = полотну.
- **F-03 [P0] [ГОТОВО]** Детерминированный компилятор промпта ИЗ структуры: near→far, позиционные слова из центра bbox (left/center/right × upper/middle/lower), палитра, свет, перспектива. Никакой ручной отсебятины. *Приёмка:* `python3 revo.py prompt layouts/datacenter.json` содержит `palette` и `perspective`; одинаковый layout → байт-в-байт одинаковый вывод.
- **F-04 [P0] [ГОТОВО]** Offline-рендер без сети и ключей: градиентная сцена, glow-слой, растворение по глубине far 0.62 / mid 0.30 / near 0.0, виньетка. *Приёмка:* `python3 revo.py render layouts/datacenter.json -o /tmp/r.png -b offline` → PNG размера полотна; работает в песочнице без сети.
- **F-05 [P0] [ГОТОВО]** `merge`: склейка «STEP 1 · LAYOUT → STEP 2 · RENDER» одним кадром. *Приёмка:* `python3 revo.py merge /tmp/s.png /tmp/r.png -o /tmp/m.png` → файл есть.
- **F-06 [P0] [ГОТОВО]** `pipeline` — v1-режим одним вызовом (skeleton+prompt+render+merge+`__run.json`). Восстановлен 2026-11-09 после обнаруженной потери в v2 (см. ОТЧЁТ). *Приёмка:* `python3 revo.py pipeline layouts/datacenter.json --outdir /tmp/p -b offline` → 5 файлов, JSON-отчёт полон.
- **F-07 [P1] [ГОТОВО]** Zai-рендер-адаптер (генеративный бэкенд через `z-ai image`), размер кратно 32 (рабочий: 1344x768). *Приёмка:* `python3 revo.py render ... -b zai` при наличии CLI; без CLI — понятная ошибка, а не падение.

### Блок B. Автономия (M1)
- **F-08 [P0] [ГОТОВО]** Мозг `compose`: ЯРУС 1 — LLM (`z-ai chat` → JSON-лейаут, любая ошибка → fallback); ЯРУС 0 — 8 архетипов (datacenter, karaoke, cyber-city, cozy-room, mountains, studio, space, cabin) + keyword-скоринг RU/EN + детерминированный поворот по SHA256. Никогда не застревает. *Приёмка:* `python3 revo.py compose "ночной дата-центр" -o /tmp/l.json` → `brain=…` + `VALID ✓`.
- **F-09 [P0] [ГОТОВО]** Критик-глаза `analyze_zones`: по каждой зоне близость среднего цвета к ожидаемому (элемент, растворённый в фоне по глубине), детальность (σ яркости), бонус за glow; итог 0..10 с весами near 1.2 / mid 1.0 / far 0.8; порог 7.5; вердикты называют зону и числа. Свой, офлайн, объяснимый. *Приёмка:* `python3 revo.py critic render.png layout.json` → JSON с `overall/zones/verdicts/pass`.
- **F-10 [P0] [ГОТОВО]** Рефайн-цикл: до 3 попыток; offline — усиление слабых зон (цвет→primary, glow), zai — жёсткие указания в промпт; лучшая попытка в `pipeline_best.png`, полный отчёт `__run.json`. *Приёмка:* `python3 revo.py auto "караоке клуб, неон" --outdir /tmp/a` → JSON с attempts/score/pass.

## 6. Нефункциональные требования

- **N-01 Offline-first:** ядро и сервер работают без сети и ключей; сеть — только опциональные бэкенды (ЯРУС 1). *Проверка:* selftest в песочнице без сети.
- **N-02 Детерминизм:** одинаковый layout → байт-в-байт одинаковый offline-рендер и промпт. *Проверка:* M2 добавит hash-сравнение в selftest.
- **N-03 Минимальные зависимости:** Python 3.9+, Pillow. Всё остальное — опционально и детектируется само.
- **N-04 Сервер — только stdlib. UI — без сборки.** Никаких npm/pip-джунглей для базового пути.
- **N-05 Числа — никогда руками:** журналы и статусы генерируются из машинных отчётов (`__run.json`).
- **N-06 CI-самодоказательство:** каждый push проходит selftest; клетка AUTO-PILOT ежедневно доказывает живость репо.
- **N-07 Онбординг агента ≤ 10 минут:** от clone до первого кадра (README quick start).
- **N-08 Адд-онли в polimat-hub:** свершившееся фиксируется raw 200; ничего не удаляется без пломбы.
- **N-09 Юридическая гигиена (см. §8):** MIT, ноль ассетов/кода/текстов Reve в репо.
- **N-10 Честный красный лучше зелёной лжи:** нерабочее помечается в README/честном статусе, не прячется.

## 8. Юридическая гигиена (обязательно)

1. В репозитории **нет и не будет** кода, весов, ассетов, логотипов, текстов или шрифта Reve.

   это чистая инженерная реставрация идеи, а не копия продукта.

4. Архив `reve-training-infra.zip` (копирайтный контент оригинала) живёт **только** в приватном
   `polimat-hub/vault/` (пломба SHA256) и локально у хозяина; в публичные репо не попадает.

## 9. Риски и честные допущения

- **Риск: expectation gap.** «100%» означает функциональный паритет (§3), не веса модели.
  зафиксировано в трёх местах, чтобы ни один агент не пообещал лишнего.
- **Риск: браузерный канвас ≠ пиксель-точность bbox.** UI пишет bbox в пикселях полотна; при
  масштабировании канваса показываем реальный размер. Принято: bbox хранится в координатах полотна.
- **Риск: zai-бэкенд недоступен в CI.** CI и AUTO-PILOT живут на offline (ЯРУС 0) — уже так.
- **Допущение: даты закрытия.** Двух источников (recraft-выписка, linearity) достаточно; если
  хозяин знает точнее — правка по коммиту с пометкой источника.
- **Ограничение: 5..8 зон у мозга ЯРУСА 0.** Оригинал масштабировал регионы до 50; наш офлайн-мозг
  скромнее, расширение — F-27 (M6). Честно указано, не скрыто.

## 10. Глоссарий

- **Layout** — структурное описание сцены: полотно, стиль, список зон (элементов).
- **Зона (element)** — id + bbox [x0,y0,x1,y1] в пикселях полотна + z (глубина) + role (описание
  на английском для компилятора промпта) + color + glow.
- **z / глубина** — far (дальний план, растворение 0.62), mid (0.30), near (0.0); порядок отрисовки far→near.
- **Скелет** — PNG-визуализация структуры: рамки зон, подписи, точка схода.
- **Компилятор промпта** — детерминированный перевод layout в текст для рендер-бэкенда.
- **Критик-глаза** — свой офлайн-анализатор соответствия рендера лейауту по зонам (score 0..10).
- **ЯРУС 0 / ЯРУС 1** — офлайн-путь без сети/ключей / усиленный путь с LLM и генеративным бэкендом.
- **Клетка (AUTO-PILOT)** — CI-обёртка автономии: ежедневно доказывает, что репо живо, кадром.
- **Пломба** — фиксация неизменяемого артефакта: копия + SHA256 в `polimat-hub/vault/`.
